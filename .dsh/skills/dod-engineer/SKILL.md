# dod-engineer:CETerm 的 Data-Oriented 工程体系

> 一句话立场:**计算机只按你的布局搬动数据。布局决定成本,抽象只有当场付了利息才配存在,不理解的代码就是负债。**

## 0. 思想谱系(理论根基)

### Jonathan Blow — 复杂度是负债,理解是主验证
- 软件失败的主因是复杂度,不是智力。任何"为未来可能需要"的结构都在**今天**兑现成本;你借的复杂度将来要连本带利还。
- 首要目标:**写你能完整理解的代码**——能在脑子里把它跑一遍。不理解的结构是债务,哪怕它"类型很安全"。
- 反对流程教条(测试文化/TDD/过度 review):工具不能替代理解。理解系统是主要验证手段;测试是补充,不是赎罪券。
- 亲自动手(Jai/自研工具链):绝不使用你看不清内部的魔法层;"它就是这样"不是答案,"它就是这些东西"才是。

### Casey Muratori — 无魔法层,层必须自己付利息
- *There is no magic.* 每一行之下是什么,你必须知道;你不知道的层 = 负债。
- **层只有当场付利息才存在**:只有当某层简化了当前真实问题(而不是可能的问题)时才加;一切为"未来/抽象/通用"预先加的层是负债而非资产。
- 反对框架与约定先行:框架契约越强,你对代码的理解被替代得越多;"约定优于配置"是放弃理解来换字面速度。
- **性能感知编程**:性能是设计出来的,不是 profile 出来的补丁。写热路径要事先知道成本(内存布局、分配、间接跳转);"过早优化"的警告不能用来掩盖"根本不知道成本"的责任。
- 测试是工具不是教条:验证你真正依赖的契约和关键路径;为覆盖而写的 mock 测试是在花 10 倍精力验证你不关心的东西。

### Mike Acton — 数据先行,抽象是敌人
- *Data-oriented design is not a technique — it's a way of thinking about problems.*
- **先设计数据,再写函数**:布局、访问模式、转换流程,然后才是操作代码。访问模式决定结构。
- 虚函数/继承是敌人:每加一层抽象,你就失去一次直接看数据的机会;多态 = enum 判别 + switch,不用类型体操。
- *Zero-risk 迷恋*(接口/框架/虚调用 = 规避"冒风险")付出的代价是 *zero-cost*(间接跳转、复制、缓存失效)的失去;没有零风险,只有权衡。
- **预算是真实的**:CPU 周期、内存带宽、分配次数。不知道成本的人没有资格写热路径代码。

### 共同内核(本规范全部条目的推演起点)
1. 数据是本体,代码是数据的搬运工
2. 理解优先:读不懂 = 负债
3. 复杂度有价:今天借,明天还
4. 默认无抽象;抽象必须当场付息
5. 显式 > 隐式:状态可见,遍历直写
6. 验证你真正关心的:不是教条,是契约

## 1. 决策序(写任何代码前先回答)

1. **数据在哪**?哪张表、什么布局、容量多少、容量上限的依据是什么?
2. **谁写、谁读**?每帧哪一趟、什么顺序访问它?访问模式与布局匹配吗?
3. **怎么引用**?跨函数只传句柄(id + 世代),不跨层传裸指针。
4. **生命周期谁负责**?谁创建谁释放;释放顺序、幂等性、悬挂自愈路径。
5. **热路径吗**?是 → 零分配、块状连续、无虚拟间接跳转、无隐藏依赖。
6. **这层抽象今天付利息了吗**?没有 → 删掉,写直白版。

## 2. 规范条目(可执行)

### 2.1 数据建模
- 槽位数组 + 分代句柄(本项目 `mem.GenArray`):定长、内联、地址稳定;槽 0 保留,`0 = null`。
- `Free` 只复位(世代 +1、槽值 `{}`、id 回池),**不深析构**;子资源清理由场景的 Destroy 显式做。
- 旧句柄一律视为"可能失效":`Get` 返回 nil 即视为未挂载,调用方不许假设句柄永远有效。
- **句柄是池的私有产品**:只能 `Alloc/AllocAt/GetHandle` 产出,只能 `Get/GetIndex/GetHandle` 取值;禁止 `池.data[句柄.id]` 直索引、手拼 `Handle{id, generation}`、裸读 `next/pool/generations`(世代校验被跳过 = 句柄抽象失效);枚举 = `Alive(i)`+`GetIndex/GetHandle(i)` 配对。
- fat struct:单实体的附随状态**内联**(`using` 提升),不为它单独建内存池。
- 值语义:小结构按值传;传指针只在"要修改"或"结构很大"。
- 一文件一数据类:数据类定义 + 生命周期 + 该数据的运算函数;文件头 1~2 行 = 数据放哪 + 关键不变量。
- 结构体默认值必须是安全空态(全零可用)。

### 2.2 遍历与帧路径
- **一次遍历只写一种数据**:每个循环要么纯读收集,要么只更新单一数据结构。
- 组合动作 = 显式分趟:**收集(纯读)→ 处理(单写)**;禁止同一循环体里顺手改多种数据。
- 帧路径分层:编排入口按数据种类组织固定有序的独立趟(布局 → 会话轮询 → 输入 → 文本路由)。
- 跨趟传递用**工作表**(标记/索引表,如 `console_geo`/`console_needs_resize`),不把副作用下压进遍历体;趟序是契约,注释写明。
- **单一真相源**:同一概念只允许一个公式/一处状态(如视口顶部只有一个 `viewportTop` 公式);派生量用 dirty 标志 + 单一入口重算。

### 2.3 模块与依赖
- 依赖图必须是 DAG,禁止环;每个数据类**唯一写者**,其他模块只读消费。
- main/编排层不实现业务,只做固定顺序调用。
- **纯状态机并入唯一消费方**(如 vtparse → `src/canvas/vtparse.odin`);保留独立包仅当:独立线程边界(conpty)、外部库边界(font)、或多个消费者。
- 对外 API 层(如 userapi)只做参数整理,不含业务。

### 2.4 接口风格
- **接口的意义 = 不变式守卫**:数据有结构正确性约束(无环/单连通/镜像/叶判定)时,设计成套操作接口集中守卫(校验只写一处,如树的 `linkSon/unlinkSon/replaceChild`),任何建/改路径必经接口,禁止裸写结构字段(zero 正确性就无所谓,接口即噪音)。
- **没有不变式的数据 = 孤立属性**:取值 = 原结构体指针 Get(`^T`)或句柄解码后**直接读写字段**;禁止值拷贝 getter(`NodeContentTransform` 式复制返回,一律删)。
- **userapi 分层**:`Set<域>`/`Get<域>`/`Reset<域>` 家族 = 用户接口(命令栏/绑定/**main.initWindows 配置段落**),保留;程序内部代码不绕 userapi,一律指针直改数据。
- 公开函数 PascalCase,模块私有小写开头(如 `ensureWindow`);外部库绑定(api.odin)不重命名。
- 错误约定:检索返回 nil/空句柄,尽力而为语义,**不抛错、不 panic**;无效输入 = 空操作,能自愈就不报错。

### 2.5 数据驱动命令
- 键位映射是**表**(`Binding{key, mods, cmd}`);命令是**数据**(`ParsedCommand`);执行走**唯一解释器**(`ExecuteCommand`)。
- 禁止在输入处理里写按键特判(`if key == X`);新动作 = 枚举新值 + 解释器分支 + 表项。
- 非法组合的校验集中化(绑定校验与匹配两处统一拒绝)。

### 2.6 并发与事件
- **拉模型**:后台线程(ConPTY 读线程)只向环形缓冲 push 字节;状态变更只发生在主线程;主循环拉取并解析。
- 事件泵单入口(`event.Update`)集中分发,输入事件不绕过泵直接改状态。
- 跨线程只交流"无锁字节搬运",不跨线程传对象/指针;帧边界清理固定位置。

### 2.7 内存与生命周期
- 预分配优先;动态数组只用于"每实例变长"(如窗口 iterms);**热路径零分配**。
- **谁创建谁清理**:子资源(console/font/iterms)由创建层负责,释放顺序反向(先子后父)。
- 销毁顺序敏感操作:**先拆引用 → 释放对象 → 最后重锚**(如销毁窗口后焦点迁移必须在树节点移除之后)。
- **公用数据引用计数**(RefCounted):获取资源 = +1,持有者释放 = -1(严格配对);归零不腾槽、句柄即失效,Alloc 满时复用 refs<=0 槽;最后释放方做深析构;释放必须经资源模块封装(如 `ReleaseFont`),禁止绕过直接 `mem.Free`。
- 数据不动就不重算;不为永远没发生的瓶颈写缓存。

### 2.8 代码表达
- 一函数一事;变量就近声明;必要抽象**第二次出现时才做**。
- **局部性最大化**:算法(DFS/BFS/搜索)的辅助状态(搜索表/栈/标记)与辅助过程(递归)全部定义在**入口函数内部**;迭代显式栈优先(免闭包、免命名,如 `LeafSplitOwner`);包级只留数据/接口/跨调用生命周期状态。
- 多态 = enum + switch(如 ToolType);无继承、无虚函数、无接口。
- 显式优于隐式:循环直接写,状态显式传递;禁止隐藏全局状态机。
- 注释精简,**只写非显然逻辑(为什么)**,中文;文件头注释是最重要的注释。

### 2.9 CETerm 项目硬性约定
- 构建:`odin build src/`(用户自行运行并粘贴输出;库源码从 `reference/` 读取)。
- 验证:行为级回归探针放 `playground/<dir>/`(`odin run playground/<dir>/`),状态可复现 + 操作序列 + 断言,不依赖 UI。
- **迁移 = 纯移动**:改逻辑与移位置分开提交;工具化迁移 + before/after 清单 + 哈希校验;**0 映射 / 目标为空 / 源缺失即中止**;先写新文件再删旧文件。
- Odin 陷阱(项目内踩过,必须回避):

| 陷阱 | 正确处理 |
| --- | --- |
| `string([]byte)` / `string(ptr)` 零拷贝 cast | 数据出作用域即悬垂;持有须 clone 或写调用方缓冲 |
| `strings.split` 零拷贝子切片 | 跨生命周期保存前 clone |
| `append(&map[k], v)` 作用于临时副本 | 先取临时绑定的 map 引用或整体重建 |
| `delete(x)` 在 `temp_allocator` 内存上 | 堆损坏(0xC0000374);`delete` 与 `new` 配对 |
| map 字面量用 `:` | Odin 用 `=`;动态 key 需 `#+feature dynamic-literals` |
| `match` / `var x : T` / `for x in [...]T{}` | 是 `switch`;用 `x := T{}`;复合字面量先赋命名变量 |
| 同包内泛型同名过程(如 GenArray 与 RefCounted 的 `Alloc/Get/Free` 同名) | 调用点解析不可靠(实测按文件序误选);不同族用前缀区分(如 `RcAlloc`) |

## 3. 检查清单(设计/评审 30 秒)

- [ ] 数据表、容量上限、遍历顺序明确且写下来了?
- [ ] 所有跨函数引用都是句柄,没有裸指针出层?
- [ ] 谁创建谁释放?销毁路径幂等?悬挂引用路径写了自愈?
- [ ] 这个循环写了几种数据?(答案必须是 1)
- [ ] 趟序是契约吗?跨趟的数据流是否经工作表显式传递?
- [ ] 热路径有没有分配/间接跳转/隐藏依赖?
- [ ] 每个抽象层今天付了利息吗?付不出来就删除。
- [ ] 有无按键特判、散落的语义分支?(应全在表里)
- [ ] 每条注释讲的是"为什么"还是"做了什么"?
- [ ] 新代码自己能否完整读懂(能在脑子里跑)?
- [ ] 有无值拷贝 getter、`池.data[句柄.id]`、手拼 `Handle`?(应全无)
- [ ] 引用计数 +1/-1 严格配对?释放走模块封装还是直接 `mem.Free`?

## 4. 反模式(发现即改)

- 同一循环里写多种数据(顺手副作用)。
- 输入处理按键特判;命令散落多入口。
- 跨模块写别人拥有的数据;管理层绕开唯一写者。
- 指针存进跨生命周期结构(只存句柄)。
- 每帧分配/释放;热路径里隐性复制。
- 为"以后可能用"加抽象层/虚函数/回调注册/框架约定。
- **值拷贝 getter**(字段复制返回);数据获取 = 原指针或句柄解码后直读字段。
- **内部代码绕 userapi**(初始化等内部逻辑调 `Set<域>`);一律 `Get<域>()` 指针直改;userapi 只给用户/配置段落。
- **绕过池抽象**:`池.data[句柄.id]` 直索引、手拼 `Handle{id, generation}`、裸读 `next/pool/generations`;一律经 `Get/GetIndex/GetHandle`。
- **算法状态污染命名空间**:DFS/搜索的工作表、栈、递归函数放模块级(应内嵌入口,迭代栈代替)。
- **引用不配对**:持引用不释放、共享借用按独有释放、越过模块封装直接 `mem.Free` 资源池引用。
- **源码副本**:测试目录复制 src 模块副本(单真相源破坏);测试 import 真实模块路径。
- 句柄失效不检查就解引用;销毁顺序错误(先重锚后拆引用)。
- 隐藏状态(隐式"上次焦点"、隐式模式开关)代替显式传递。
- 用测试教条覆盖代替理解;为覆盖而 mock 全部。
- 迁移代码时顺手改行为。
- 注释解释"做了什么"而回避"为什么";文件头没有数据与不变量说明。
