# CETerm 编码规范(以 DOD 为核心)

> 数据导向设计(Data-Oriented Design):
> **先想数据怎么存、怎么被遍历,再写操作它的代码。**
> 结构(布局)决定性能与复杂度,算法其次。本规范所有条目都是这一条的下游推论。
>
> 完整体系(理念 + 规范 + 检查清单)见 skill:`dod-engineer`
> (`.dsh/skills/dod-engineer/SKILL.md`)。

---

## 0. 理念根基(批判理论)

本规范不是风格偏好,而是三条批判性结论的工程化:

**Jonathan Blow — 复杂度是负债,理解是主验证**
- 软件失败的主因是复杂度;任何"为未来"的结构都在今天兑现成本,借的复杂度要连本带利还。
- 首要目标是写**能完整理解**的代码(能在脑子里跑一遍);不理解的结构是债务,哪怕类型很安全。
- 工具(测试文化/TDD/review 教条)不能替代理解:理解是主要验证,测试是补充。

**Casey Muratori — 无魔法层,层必须付利息**
- *There is no magic*:每一层下面是什么必须知道;不知道的层 = 负债。
- 层只在**当场付息**时存在(简化了当前真实问题);为"可能"预加的层是负债,不是资产。
- 反对框架/约定先行:契约越强,对代码的理解被替代得越多。
- 性能是设计出来的,不是 profile 出来的:热路径要事先知道成本;"过早优化"的警告不能掩盖"不知道成本"。
- 测试验证**真正依赖的契约**,不为覆盖而 mock 全部。

**Mike Acton — 数据先行,抽象是敌人**
- *Data-oriented design is not a technique — it's a way of thinking about problems.*
- 先设计数据(布局/访问模式/转换),再写函数;访问模式决定结构。
- 虚函数/继承是敌人:每加一层抽象就失去一次直接看数据的机会;多态 = enum + switch。
- Zero-risk 迷恋(接口/框架/虚调用)以 zero-cost(间接跳转/复制/缓存失效)为代价;没有零风险,只有权衡。
- 预算是真实的:周期、带宽、分配次数。不知道成本的人没资格写热路径。

**共同内核(本规范全部条目的推演起点)**
1. 数据是本体,代码是数据的搬运工
2. 理解优先:读不懂 = 负债
3. 复杂度有价:今天借,明天还
4. 默认无抽象;抽象必须当场付息
5. 显式 > 隐式:状态可见,遍历直写
6. 验证你真正关心的:不是教条,是契约

## 1. 数据建模

### 1.1 布局先行

- 写任何功能前,先回答:数据放哪张表?how 被谁遍历?遍历顺序是什么?
- 布局为遍历服务:同趟要连续访问的数据放同一张表;一表一数据类。
- 容量即预算:`GenArray(N, T)` 的 N 是对资源上限的显式声明,在文件头注明依据,不许随手填。

### 1.2 槽位数组 + 分代句柄

- 资源存定长数组(`GenArray`/`RefCounted`),函数间传 `mem.Handle{id, generation}`,不传裸指针、不跨层传指针。数据连续、无悬挂、遍历局部性好。
- **句柄是池的私有产品**:只能由 `Alloc/AllocAt/GetHandle` 产出;取值只能经 `Get/GetIndex/GetHandle`(带世代校验)。
- **禁止绕过池抽象**:不许 `池.data[句柄.id]` 直接索引(世代校验被跳过,句柄失效/复用后静默读到脏数据);不许手动构造 `Handle{id, generation = 池.generations[i]}`——那是 `GetHandle` 的活。
- 例外(注释必须写明):自定义句柄编码(如 vt 的 `v>>32` 世代)与非池属的并行裸数组(如 `read_write_datas[h.id]`,与主池同下标、无世代)。
- 槽 0 保留,存活 id 从 1 起;`0 = null/空`。
- `Free` 只做三件事:世代 +1、槽值复位 `{}`、id 回池。**不做深析构**——释放策略(子资源清理)由场景定,谁创建谁负责。
- 句柄无生命周期义务:旧句柄一律按"可能失效"处理,`Get` 返回 nil 即自愈,调用方不许假设句柄永远有效。
- 枚举配对:`Alive(i)` + `GetIndex(i)`/`GetHandle(i)`,不单独触碰 `next/pool/generations`;`Alive` 是 O(pool) 冷路径,不进热循环。

### 1.3 一文件一数据类

- 每个数据类一个文件:`数据类定义 + 生命周期函数 + 该数据的运算函数`(如 `win.odin` = Window,`tree.odin` = WindowTreeNode,`buffer.odin` = TermBuffer)。
- 文件头 1~2 行:数据放哪、由谁挂载、关键不变量。字段的不显然语义写行内注释。
- 生命周期(创建/销毁/挂载/拆挂)归数据类文件,不散落在编排层。

### 1.4 fat struct,不搞对象池

- 一个实体需要的状态**内联**进它的结构(如 `using commandbar : CommandBar` 直接提升进 Iterm)。
- 只有"同类多实例、生命周期独立"才进槽位数组;单个附随状态用 fat struct,禁止为它单独建内存池。

### 1.5 值语义

- 小结构按值传/返回;复制成本低就不传指针。传递指针只出现在"要改数据"或"结构很大"时。
- 结构体默认值必须是安全空态(全零可用):`Window{}`/`Handle{}` 都能被安全消费。

## 2. 模块与依赖

### 2.1 DAG,禁止环

- 依赖图必须是有向无环图。上游不知道下游存在;单向消费。
- 判据:跨模块引用 = 依赖;模块之间靠**上游导出、下游导入**的函数与本模块私有数据,下游不得回写上游状态。

### 2.2 模块职责边界

- **数据拥有者 = 唯一写者**:一个数据类只被一个模块写,其他模块只读(如 render 对 canvas 只读消费)。
- **编排层(Update)不实现业务**:main 只做固定顺序调用;业务实现在模块内。
- **薄用户 API 层**:对外函数族(如 userapi)只做参数整理 + 调用内部实现,不含业务逻辑。

### 2.3 纯状态机并入唯一消费方

- "纯状态机、只被一个模块消费、无独立演化需求"的实现**并入消费方模块**文件(如 vtparse → src/canvas/vtparse.odin),不单独成包。
- 保留独立包的判据:有独立线程边界(conpty)、外部库边界(font)、或会被多个模块消费。

### 2.4 main 只做编排

- `main` 只包含:初始化、固定有序的帧循环调用、退出清理。不写分支逻辑、不放业务、不给 import 起别名。

## 3. 接口风格

### 3.1 接口的意义 = 不变式守卫(先判数据,再定接口)

- **接口的存在理由是数据结构正确性(不变式)**:当"无论调用方怎么调用,结果数据一定合法"是要求时,才设计接口(校验/连接/联动)。例:窗口树的结构正确性(无环、单连通、父指针与子指针镜像、叶判定)由 `linkSon/unlinkSon/replaceChild` 三件套守卫 —— 任何建树/改树路径必经接口,禁止裸写 `parent_id/left_son_id/right_son_id/is_leaf`。
- **孤立属性不需要接口**:一个字段赋值不影响任何其他数据、无约束可破坏(如 `focused`、`auto_close`、主题颜色),直接 `GetXxx().field = ...` / 裸赋值,提供专门接口反而是噪音(`SetFocus/GetFocus` 已删)。
- 判据流程:这个数据有没有结构不变式?有 → 接口成套(覆盖所有合法操作 + 集中校验,如环检测只写一处);没有 → 无接口。
- 接口守卫的不变式要**写明**(函数群上方注释:不变式清单 + 破坏方式),并用校验器回测(如 treetest 每步后验证无环/镜像/单连通)。

### 3.2 纯赋值/纯读取不提供接口

- 数据的获取 = **原结构体指针**的获取函数(`GetXxx :: proc() -> ^T`),或句柄解码(`GetConsole/GetFont/GetWindowTreeNode`)之后**直接读写字段**。只有设计运算抽象(校验、clamp、联动副作用如重算布局)时才暴露函数(如 `TreeNodeSetSplitFactor`)。
- **禁止"值拷贝 getter"**:任何把字段逐字段复制成新值返回的函数(`NodeContentTransform` 式)一律删除;调用方 `GetXxx().field` 直取。
- 例:`window.position_x = ...` 直接写;`applyConsoleSize`(联动重算)才是函数;`current_theme` 用 `GetTheme()^` 读改,`SetTheme(整表替换)` 仅作为 userapi 保留。

### 3.3 userapi 分层(对外接口 vs 内部代码)

- **userapi(`Set<域>`/`Get<域>`/`Reset<域>` 家族)是给用户的接口**:命令栏字符串命令、快捷键绑定、配置段落(main.initWindows = 配置文件立场)直接使用,必须保留。
- **程序内部代码不得绕 userapi**:内部读写一律 `GetXxx()` 指针直接操作数据;内部调用 userapi 的 Set 系列 = 滥用(键位/主题/启动/字体等**用户配置一律写在配置文件 `resource/config.ceterm`,经指令行生效**,不在代码里循环调 Set 系列)。
- 唯一例外:main 的 initWindows 类初始化函数(以"配置者"身份调用 userapi,语义 = 用户配置)。

### 3.4 命名

- 公开函数 PascalCase;模块私有函数小写开头(如 `ensureWindow`)。
- 外部库绑定(api.odin)不重命名,按 SDK 原名。
- 变量就近、语义化;不缩写到不可读,不为短命名牺牲直白。

### 3.5 错误约定

- 检索类函数:`Get`/`Find` 返回 nil(或 bool),**不抛错、不 panic**。调用方处理 nil = 空态。
- "尽力而为"语义优先:无效句柄 = 空操作;能自愈不要报错。

## 4. 遍历与每帧路径

### 4.1 一次遍历只写一种数据

- 每个循环要么**纯读收集**,要么**只更新单一数据结构**。
- 组合动作 = 显式分趟:**收集(纯读)→ 处理(单写)**;禁止在同一循环体里顺手改多种数据、搞不清副作用。

### 4.2 每帧路径分层

- 编排入口(Update)按**数据种类**组织成固定、有序的独立趟(如 canvas.Update = 树布局 → 会话轮询 → 输入 → 文本路由)。
- 跨趟传递用**工作表**(标记/索引表,如 `console_geo`/`console_needs_resize`),不把副作用下压进遍历体。
- 趟的顺序是契约:上游趟的结果是下游趟的输入,注释里写明。

### 4.3 单一真相源

- 同一个概念只允许一个公式/一处状态(如视口顶部只有 `viewportTop` 一个公式,渲染/CPR/缩放共用;`review_line` 是历史视口的唯一锚点)。
- 派生值不落两个地方;需要"缓存"时用 dirty 标志 + 单一入口重算。

## 5. 数据驱动命令

- **键位映射是数据**:`Binding{key, mods, cmd}` 表;键位与行为的对应关系只存表里,禁止在输入处理里写 `if key == X` 特判。
- **命令是数据**:统一命令结构(如 `ParsedCommand{kind, target, dir, ...}`)+ **唯一解释器**(`ExecuteCommand`);新动作 = 枚举新值 + 解释器分支 + 表项,不新增散落的 if。
- 校验规则也数据化/集中化(如非法组合在绑定校验与匹配两处统一拒绝)。

## 6. 并发与事件模型

- **拉模型,不推模型**:后台线程(ConPTY 读线程)只向环形缓冲 push 字节;**主循环拉取并解析**。状态变更只发生在一个线程(主线程)。
- 事件泵单入口:`event.Update` 集中分发;窗口/输入事件不绕过泵直接改状态。
- 跨线程交流的只有"无锁的字节搬运",不跨线程传对象/指针。
- `BeginFrame`/`EndFrame` 成对出现,帧边界清理(如输入边沿)在帧内固定位置。

## 7. 内存与生命周期

### 7.1 预分配,不为热路径分配

- 固定容量数组优先(`GenArray`/`[N]T`);动态数组只用于"每实例变长"(如窗口的 iterms 数组),按需扩容,**不在每帧路径分配**。
- 热路径(渲染、布局、解析)禁止分配/释放。

### 7.2 所有权:谁创建谁清理

- 槽位对象的子资源(console、font、iterms)由**创建它的那一层**负责释放;释放顺序反向(先子后父)。`Free` 只复位,深释放显式写在对应 Destroy 函数里。
- 销毁接口要处理"目标已失效/已销毁"的幂等情况。

### 7.3 悬挂句柄自愈

- 任何跨表引用(窗口挂 console、节点挂窗口)在引用方被销毁时,**主动清引用**;清理不了时,用句柄失效检测兜底(Get 返回 nil 即视为未挂载)。
- 销毁顺序敏感的操作:**先拆引用、再释放对象、最后重锚**(如销毁窗口后焦点迁移要等树节点移除完成后进行)。

### 7.4 数据不动就不重算

- dirty 标志、增量计算;不为永远没发生的瓶颈写缓存。
- 布局/视口等派生量,只在输入变化的那一帧重算,不每帧全量。

### 7.5 引用计数池(RefCounted):公用数据

- `RefCounted` = `GenArray` + 引用计数,只用于**公共数据**(如字体:同 path+size 跨窗口/UI 共享),不用"引用集扫描"模拟共享(扫不到的持有者会被误清,如 UI 字体)。
- **引用纪律**:
  - `LoadFont` 类"获取资源" = 获得一个引用(+1);每个持有者(窗口、UI 单例)持有一个引用,释放时必须 -1 —— 持有者在哪,配对就在哪(窗口槽释放、UI 字体替换/重置)。
  - `Free` = 引用 -1;**归零不腾槽**(句柄随即失效),`Alloc` 无空位时自动复用 `refs <= 0` 的槽(世代 +1,旧句柄作废);全部引用在用 = 表满失败。
  - **最后引用的释放方做深析构**(T 的堆资源);持有者释放必须经资源模块的封装(如 `ReleaseFont`),禁止绕过直接 `mem.Free`。
  - 引用归零的句柄 `Get` 立即失效:谁持有谁引用,释放即作废(不提供"弱引用"后门)。

## 8. 直白代码

- 一个函数干一件事;变量就近声明(用时才声明)。
- **局部性最大化**:算法的辅助状态(搜索表/栈/标记)与辅助过程(递归/DFS 函数)全部定义在**入口函数内部**,不进入包命名空间;包级只保留数据、接口、跨调用生命周期状态。
  - 实现手法:迭代显式栈代替递归(免闭包、免命名);表 = 入口内的命名数组 + 计数(如 `LeafSplitOwner` 的 `order/owner/dfs/claim` 全内嵌)。
  - 例外(须注明):无状态纯递归工具(`firstLeaf` 等,不携带状态);热路径跨帧复用缓冲(如渲染 shaping 缓冲,零分配设计的模块级复用)。
- **不做"为未来"的抽象**:必要抽象在第二次出现时才做;第一次出现写直白版。
- 多态用 `enum + switch`(如 ToolType),无继承、无虚函数、无接口。
- 显式优于隐式:循环直接写,状态显式传递;禁止隐藏的全局状态机(如隐式的"上次状态")。
- 简单 > 聪明:不追求表达力的炫技,追求读一遍就懂。

## 9. 注释与文档

- 注释精简,**只写非显然逻辑**(为什么,而不是做什么),中文。
- 文件头注释 = 数据布局 + 不变量(这是最重要的注释,新人读它建立心智模型)。
- 字段行内注释只解释"语义/约定"(如 `id 0 = 空`、`generation 仅在 Free 时 +1`),不解释显而易见的类型含义。
- 大文件内用分隔注释块区分逻辑段(`----` 行)。

## 10. 验证与演化

### 10.1 验证文化

- 每个里程碑后:`odin build src/` 必须通过(用户自行构建并粘贴输出);行为级验证用 `playground/` 下的回归探针(`odin run playground/<dir>/`)。
- 探针写"可复现的初始状态 + 操作序列 + 断言",能独立重现功能路径,不依赖 UI。

### 10.2 迁移 = 纯移动

- **代码迁移不改语义**:移动 = 换位置,不允许顺手改逻辑。改逻辑与移位置分开提交。
- 大批量迁移前打安全提交;用工具化迁移(输出 before/after 清单 + 哈希校验),**规则:任何目标为空/映射失败即中止**,先写新文件再删旧文件。
- 迁移后验证:声明完整性 + 构建 + 探针全绿,才算完成。

### 10.3 Odin 陷阱清单(项目内踩过的)

| 陷阱 | 正确处理 |
| --- | --- |
| `string([]byte)` / `string(ptr)` 是零拷贝 cast | 数据出作用域会悬垂;要持有须 clone 或写入调用方缓冲 |
| `strings.split` 返回零拷贝子切片 | 跨生命周期保存前 clone |
| `append(&map[k], v)` 作用于临时副本 | 先取 `m := &map[k]` 或整体重建 |
| 在 `temp_allocator` 内存上 `delete` | 堆损坏(0xC0000374);用默认 allocator 或 `delete` 匹配 `new` |
| map 字面量用 `:` 分隔 | Odin 用 `=`;动态 key 需 `#+feature dynamic-literals` |
| `match` / `var x : T` / `for x in [...]T{}` 字面量 | Odin 是 `switch`;用 `x := T{}`;复合字面量先赋给命名变量 |
| 同包内泛型同名过程(如 GenArray 与 RefCounted 的 `Alloc/Get/Free` 同名) | 调用点解析不可靠(实测按文件序误选);不同族用前缀/区分命名(如 `RcAlloc`) |

## 11. 反模式清单(发现即改)

- 同一循环里写多种数据(多"顺手"副作用)。
- 输入处理里的按键特判(`if key == F2` 之类)——应进绑定表。
- 跨模块直接改别人拥有的数据(绕过模块写者)。
- 把指针存进跨生命周期结构体(只存句柄)。
- 每帧分配/释放。
- 为"以后可能用"加抽象层、虚函数、回调注册。
- **值拷贝 getter**:把字段逐字段复制成新值返回(`NodeContentTransform` 式);数据获取 = 原指针或句柄解码后直读字段。
- **内部代码调用 userapi 的 Set 系列**(在代码里循环调 `SetKeyBinding` 之类);用户配置走配置文件指令行,内部一律 `GetXxx()` 指针直改。
- **绕过池抽象**:`池.data[句柄.id]` 直索引、手动拼 `Handle{id, generation}`、裸读 `next/pool/generations`——一律经 `Get/GetIndex/GetHandle/Alloc`。
