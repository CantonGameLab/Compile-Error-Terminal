# OSC 序列总览(CETerm 实现的全部 OSC)

> 本文件是**索引与总览**:列出 CETerm 实际处理的每一个 OSC 号码、格式、行为与权限。
> 单条协议的深入细节按表里的链接去看专文。
>
> 实现落点:`src/canvas/vt.odin` 的 `oscDispatch`(分派)· `oscParseHead`(头解析)。
> 缓冲区:`OSC_BUFFER = 4096`(`osc_data`,包级复用)。
> 子进程命令信道(999)协议见 [`OSC999.md`](OSC999.md);架构与数据结构见 [`DESIGN.md`](DESIGN.md)。

---

## 1. 共同的语法与限制

### 1.1 序列形态

```
ESC ] <号码> ; <载荷> <ST>
```

- 引导:`0x1B 0x5D`(`ESC ]`)
- 终止:`ESC \`(ST,两字节);**`0x07`(BEL)也能终止**,是 xterm 兼容写法
- 头解析 `oscParseHead`:**号码必须是纯十进制**,后跟一个 `;`
  - 号码为空、或后面不是 `;` → **整条丢弃**(不算错误,静默)
  - 号码后**第一个 `;` 之后全是载荷**(载荷里可以有 `;`)

```
ESC]0;my title ST          →  num=0   payload="my title"
ESC]7;file://host/C:/x ST  →  num=7   payload="file://host/C:/x"
ESC]52;c;YWJj ST           →  num=52  payload="c;YWJj"
```

### 1.2 载荷的字节限制(**决定了协议为什么长这样**)

`tr_osc_string`(`src/canvas/vtparse.odin`)对载荷字节有硬性分类:

| 字节范围 | 处理 |
|---|---|
| `0x20-0x7F` | 收入载荷 |
| `0x80-0xFF` | 收入载荷(UTF-8 多字节字符) |
| `0x00-0x17`、`0x19`、`0x1C-0x1F` | **`Ignore` —— 静默丢弃** |
| `0x07`(BEL) | 终止序列 |
| `0x18`(CAN)、`0x1A`(SUB) | 截断 |
| `0x1B`(ESC) | 进入 ST 路径(即 `ESC \` 终止) |

**两个后果,贯穿所有 OSC 协议**:

1. **控制字节物理上带不进来**。所以 `ESC]999;feed "\r" ST` 里的 `\r` 会被静默吞掉 ——
   这就是为什么 `feed` 的参数要支持**文本转义**(见 [`SCRIPT.md`](SCRIPT.md) §5.1)。
2. **总长上限 4096**。超长段**整段作废**(`osc_bad` 标记),绝不执行被截断的序列 ——
   截断 = 执行另一条命令。

### 1.3 回写方向

CETerm 的应答经 `oscReply` 写进**子进程的 stdin**。而 **stdin 同时是键盘输入流**,
所以应答的每个字节都是一次"按键"。这条约束派生出 OSC 999 的全部防注入规则
(见 [`OSC999.md`](OSC999.md) §1.2、§7)。

## 3. 逐个说明

### 3.1 OSC 0 / 1 / 2 —— 窗口标题

```
ESC]0;<title> ST     图标名 + 窗口标题(一起设)
ESC]1;<title> ST     仅图标名
ESC]2;<title> ST     仅窗口标题
```

**行为**:

- `0` 与 `2` 等价处理:把 `<title>` 存进 `Console.app_title`(`oscSetAppTitle`)
- `<title>` 为**空** = 清除(回到启动标题)
- 长度截到 `APP_TITLE_MAX`,超出部分丢弃
- `1`(图标名)**忽略** —— 终端没有图标概念(xterm 里它设的是最小化后的图标标签)

**与页标题的关系(重要)**:

| | 显示在哪 | 谁写 |
|---|---|---|
| `Console.app_title` | **OS 窗口标题栏** | 程序(OSC 0/2) |
| `Page.title` | **页签条** | 用户(命令 `page-title` / `page-new`) |

**两者互不覆盖** —— 用户给页起的名字不会被程序自报的标题冲掉。
OS 标题由 `render.SyncWindowTitle(canvas.FocusedAppTitle())` 每帧同步(仅变化时落 SDL)。

程序侧示例:

```sh
printf '\033]2;building...\033\\'     # 设标题
printf '\033]2;\033\\'                # 清除
```

### 3.2 OSC 7 —— 当前工作目录

```
ESC]7;file://<host>/<path> ST
```

**行为**(`oscSetCwd` + `cwdNormalize`):

1. 载荷**必须以 `file://` 开头**,否则忽略(程序乱发很常见)
2. **跳过 host 段**(第一个 `/` 之前):`file://myhost/C:/x` 与 `file:///C:/x` 等价
3. 路径段做**百分号解码**(`%20` → 空格等)
4. 记在**该会话**名下(`Console.cwd`),不写全局 —— shell 每个提示符都上报,
   写全局会被多窗格互相覆盖
5. 形态归一(消费端是 `CreateProcess` 的 `lpCurrentDirectory`):

| 输入形态 | 归一为 |
|---|---|
| `/C:/Users/x` | `C:\Users\x`(URL 前导 `/` 去掉) |
| `/c/Users/x` | `C:\Users\x`(msys2 风格;小写盘符转大写) |
| `C:/Users/x` | `C:\Users\x`(只统一分隔符) |
| 其他 | 原样 |

**用途**:`cwd` 命令可以查"焦点会话报告的工作目录";新建会话继承它。

程序侧示例(shell 提示符钩子里):

```sh
printf '\033]7;file://%s%s\033\\' "$HOSTNAME" "$PWD"
```

### 3.3 OSC 52 —— 剪贴板

```
ESC]52;<选择区>;<base64 数据> ST      写剪贴板
ESC]52;<选择区>;? ST                  读剪贴板(终端回一条 OSC 52)
```

**行为**(`oscClipboard` / `oscReplyClipboard`):

- `<选择区>` **被丢弃**,不区分 —— CETerm 没有 xterm 那套选择区存储:
  `c` / `p` / `s0`-`s7` 效果**完全相同**,都操作系统剪贴板
- 数据是 **base64**;解码失败(非法 base64)则**整条忽略**,不动剪贴板
- `?` = 查询:终端回写一条 `ESC]52;c;<base64> ST` 到子进程 stdin
- 空数据 = 清空剪贴板
- **读方向的截断**:内容超过 `OSC_BUFFER - 32` 时按 **4 字节边界**截断
  (保证 base64 仍然合法,不会输出半组编码)
- 空剪贴板 → 回 `ESC]52;c; ST`(数据段为空)

**注意**:读方向的应答同样进 stdin(键盘流)—— 和 OSC 999 一样的纪律,
只有**自己读 stdin 的程序**能可靠收到。

程序侧示例:

```sh
printf '\033]52;c;%s\033\\' "$(printf 'hello' | base64)"   # 写
printf '\033]52;c;?\033\\'                                  # 查询
```

### 3.4 OSC 999 —— 子进程命令信道

**这是 CETerm 自己的扩展**,不是通用终端协议。它让子进程直接给终端下命令
(分裂窗格、设主题、读屏幕内容…),回执经同一号码写回。

```
请求:  ESC]999;<命令串> ST
应答:  ESC]999;>ok;<正文> ST
       ESC]999;>err;<原因> ST
       ESC]999;>ok;? ST            成功但没有正文
```

**必须先授权**:该窗格要先用命令栏的 `osc on` 授权 —— 有 poll = 已授权。
未授权时 OSC 999 被当作**未知号码静默忽略**(连"被拒"都不回)。

完整协议(三条硬约束、方向标记、ret 三态、定序、信道教码、不变式)见
**[`OSC999.md`](OSC999.md)**。命令串本身的语法见 [`SCRIPT.md`](SCRIPT.md)。

## 4. 未实现的号码(明确忽略)

以下号码 CETerm **静默忽略**(不报错、不回复)。列出来是为了说明"忽略是有意的,
不是漏了",以及将来若要实现该往哪加。

| 号码 | 标准用途 | 若实现要动的地方 |
|---|---|---|
| 4 | 设置/查询颜色(改调色板) | `oscDispatch` + 主题系统 |
| 8 | 超链接(`ESC]8;;url ST` 包住文本) | 需要 cell 级属性 + 命中测试 |
| 9 | 通知(iTerm2/Windows Terminal 风格的桌面通知) | 需要平台通知 API |
| 10 / 11 / 12 | 查询前景/背景/光标色 | 读主题,回 `OSC 1x;rgb:...` |
| 104 | 重置颜色 | 主题系统 |
| 110 / 111 / 112 | 重置前景/背景/光标色 | 主题系统 |
| 133 | 命令标记(shell 集成:提示符/命令起止) | 需要行级标记 + 跳转 UI |
| 1337 | iTerm2 私有(图片等) | — |
| 998 | 曾规划作"回执通道" | **已废弃**:回执并入 OSC 999(见 `OSC999.md` §12) |

**加新号码的做法**:在 `oscDispatch` 的 `switch num` 里加一个 `case`,载荷已解析好;
若需要回写,用 `oscReply(console_h, msg)`(它自己拼 `999;` 前缀是为 999 用的,
其他号码需要各自的拼装)。**注意**:回写进的是 stdin,必须满足 §1.3 的约束。

## 5. 不变式清单(可断言)

1. `oscParseHead` 只在"号码非空 **且** 紧跟 `;`"时成功;否则整条丢弃
2. 载荷**不可能含** `0x00-0x1F`(除被状态机特殊处理的终止/截断字节)—— 这是
   `tr_osc_string` 的 `Ignore` 保证的,不依赖上层再过滤
3. 载荷总长 ≤ `OSC_BUFFER`(4096);超长 = **整段作废**,绝不执行半条
4. OSC 0/2 只写 `Console.app_title`;**永不触碰** `Page.title`
5. OSC 1 无副作用
6. OSC 7 只在 `file://` 前缀下生效;cwd 记在**会话**上,不写全局
7. **OSC 52 与 OSC 999 的应答都写进 stdin**(键盘流)—— 消费方必须自己读 stdin。
   两者共用 `oscReply`(唯一出口),它的副作用是:无会话的 console 直接不发
   (`conpty_handle.id == 0` 早退),消息按 `OSC_BUFFER - 8` 截断
8. OSC 999 未授权时**零可观察效果**(不执行、不入队、不回复)
9. 未列出的号码一律静默忽略,**不回任何东西**
